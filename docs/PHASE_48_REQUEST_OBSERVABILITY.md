# 第 48 阶段：请求关联与结构化日志

## 目标

为每个 HTTP 请求建立可追踪的关联 ID，并将请求方法、路径、状态码和耗时写入结构化日志。后续运行、审批和事件流可以使用同一关联 ID 进行检索。

## 关联 ID 规则

客户端可以通过 `X-Request-ID` 传入关联 ID。Harness 仅接受长度不超过 128、且只包含字母、数字、连字符和下划线的值。

未提供或不符合规则时，服务生成 32 位十六进制 UUID，并通过响应头 `X-Request-ID` 返回。

## 日志字段

每次成功完成的 HTTP 请求至少记录以下字段：

- `request_id`
- `http_method`
- `http_path`
- `status_code`
- `latency_ms`

日志使用 JSON 输出。关联 ID 只用于请求追踪，不包含 API 密钥、数据库地址或模型供应商凭据。

## 限制

本阶段只记录 HTTP 请求层信息。诊断运行、工具调用和审批事件尚未写入同一日志链路，后续阶段会在服务层调用 Harness 时补充这些字段。
