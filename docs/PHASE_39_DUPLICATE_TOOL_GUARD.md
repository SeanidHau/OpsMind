# 第 39 阶段：重复工具调用前置阻断

## 目标

将重复工具调用检查前移到 `ActionPolicy`。Harness 在调用工具之前，检查当前运行中是否已经成功执行过相同工具和相同参数的动作，避免模型重复消耗工具预算。

## 检查范围

重复调用满足以下条件：

- 动作类型为 `call_tool`；
- 工具名称相同；
- `tool_args` 完全相同；
- 历史动作已产生 `TOOL_FINISHED` 事件。

工具失败后的自动重试不经过 `ActionPolicy`，因此不受本规则影响。相同工具使用不同参数时，仍可执行并收集新的证据。

## 执行顺序

`call_tool` 动作按以下顺序经过策略层：

1. 检查工具是否注册。
2. 检查工具参数是否符合注册定义。
3. 检查是否达到相同工具参数的成功调用上限。
4. 检查预算。
5. 检查风险审批要求。
6. 执行工具。

重复调用被阻断时，不会执行工具，也不会增加 `used_tool_calls`、`tool_call_count` 或 `used_steps`。

## 配置

`ActionPolicy` 的 `max_identical_tool_calls` 默认值为 `1`。默认情况下，同一工具与相同参数成功执行一次后，后续重复调用会被阻断。

测试或需要刷新数据的受控场景可以显式提高该值。该配置只放宽同一调用的成功次数，不改变工具重试策略。

## 阻断结果

策略层返回 `PolicyOutcome.BLOCK`：

- 原因：`同一工具及参数已成功执行，拒绝重复调用。`
- 违规标识：`tool:duplicate_call`

## 验收覆盖

- `tests/test_action_policy.py` 验证重复调用阻断、不同参数放行和可配置调用上限。
- `tests/test_harness_loop.py` 验证重复调用不会再次触发工具执行或消耗工具预算。
