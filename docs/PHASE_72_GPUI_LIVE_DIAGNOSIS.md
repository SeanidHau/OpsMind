# 第 72 阶段：GPUI 实时诊断

本阶段将桌面端的诊断输入、SSE 传输和运行轨迹面板连通。用户在输入框按 `⌘↵` 或点击“开始诊断”后，桌面端会向后端发起一次流式诊断请求。

## 运行模型

- 桌面端在应用启动时生成会话 ID 和线程 ID；同一次应用会话中的诊断请求复用这两个 ID。
- 后台执行器负责发起 HTTP 请求并读取 SSE 分块，不在 GPUI 前台线程执行阻塞 I/O。
- 后台任务将已解析的 SSE 事件通过异步通道投递给前台执行器。
- 前台执行器只更新 `OpsMindConsole` 状态并触发重绘，因此输入和窗口交互不会等待模型运行结束。

## 轨迹展示边界

轨迹面板只接收事件名与安全投影字段：`step_id`、`tool_name`、`latency_ms`。展示内容不包含模型输出、观察结果、工具参数、决策文本、错误详情或其他未声明字段。

面板最多缓存 12 条轨迹事件，并显示最近 3 条。未知事件名、事件名与负载中的 `event_type` 不一致的事件，以及缺少步骤 ID 的事件都不会进入界面。

## 交互状态

- 后端不可用时，开始按钮保持禁用。
- 运行期间禁止重复提交，状态区显示已接收的安全轨迹事件数量。
- 收到 `run_finished` 后，状态区只显示受控状态值和步骤数。
- 请求失败或收到 `run_failed` 后，界面只显示通用失败状态，不向用户暴露底层异常信息。

## 验证范围

Rust 单元测试覆盖 SSE 分块解析、非 JSON 负载拒绝、轨迹字段投影和未知事件拒绝。完整验收还包括 Rust 编译检查，以及 Python 服务端的测试、静态检查和类型检查。
